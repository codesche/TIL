
## TIL 주제
- ORM

## 주요 내용


### ORM이란?
- ORM(Object-Relational Mapping)은 객체 지향 프로그래밍 언어를 사용하여 호환되지 않는 유형의 시스템 간에 데이터를 변환하는 프로그래밍 기술이다.
- 객체와 관계형 데이터베이스의 데이터를 매핑.
- ORM을 사용하면 SQL 쿼리 없이 데이터를 데이터베이스에 저장하고 관리할 수 있음.

### ORM의 주요 기능과 장점
- ORM의 주요 기능으로는 객체와 테이블 간의 매핑, 데이터 쿼리 및 조작, 트랜잭션 관리 등이 있다.
- 이러한 주요 기능을 통해 객체 지향적인 방식으로 데이터베이스를 조작할 수 있게 해준다.
- ORM은 데이터베이스 설계 변경 시에도 코드의 대대적인 수정 없이 유연하게 대응할 수 있게 해준다. => 구조가 변경되어도 객체 모델을 쉽게 수정할 수 있음
- ORM의 사용은 코드의 가독성을 높이고, 유지 보수를 용이하게 해주며, 데이터베이스와의 결합도를 낮출 수 있는 장점이 있다.
- ORM의 사용은 데이터베이스의 독립성을 제공한다. 즉, 애플리케이션 코드를 변경하지 않아도 다른 유형의 데이터베이스로 쉽게 전환할 수 있다.

### ORM 사용 시 고려사항
- 성능 저하
  - ORM이 생성하는 SQL 쿼리가 최적화되지 않을 경우 발생(ex. JPA의 N + 1 문제).
- 복잡한 쿼리 처리하는 데 한계가 있음
  - ORM은 대부분의 데이터베이스 작업을 간단하게 만들어 주지만, 매우 복잡한 쿼리나 최적화가 필요한 경우 직접 SQL을 작성하는 게 더 효과적일 수 있다.
  - ORM은 복잡한 쿼리를 추상화하는 과정에서 세밀한 제어를 제공하지 못하는 경우가 발생할 수 있음.
- 객체 모델과 데이터베이스 모델 간의 불일치 문제를 고려
  - 객체 지향 모델과 데이터베이스 모델 사이에는 구조적인 차이가 있음.
  - 불일치를 해결하기 위한 추가적인 설정이나 코드가 필요할 수 있음.
  - 불일치 문제를 충분히 이해하고 대비하는 것이 좋음.

## 정리
- ORM을 효과적으로 사용하려면 ORM의 작동 원리를 이해하고, 성능과 복잡성, 데이터 모델의 불일치 문제에 대해 고려해야 한다.
- ORM의 내부 동작과 SQL 쿼리 생성 방식을 이해하고 사용해야 단점을 최소화할 수 있다.
- 복잡한 쿼리가 필요한 경우 직접 SQL 쿼리를 작성한다.
